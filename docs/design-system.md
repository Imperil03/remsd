# REMSD Design System Contract

Этот документ фиксирует кодовый контракт визуальной системы РемСД. Визуальное направление и иерархия источников описаны в `docs/design-guideline.md`; утверждённый внешний референс блоков хранится в `docs/references/internal-hub-block-reference.png`.

## Слои CSS

Исходные слои подключаются сборщиком в фиксированном порядке:

1. `assets/css/design-system.css` — глобальные токены и единственный `:root`.
2. `assets/css/styles.css` — variable fonts, reset, `body`, `.container` и общие основы.
3. `assets/css/site-chrome.css` — шапка, меню, футер, skip-link, mobile callbar, единая `.v3-button` и служебная 404.
4. `assets/css/styles-v3.css` — композиция только главной.
5. `assets/css/internal-pages.css` — композиционные модули внутренних страниц.

Публичные бандлы:

- `base.css = design-system.css + styles.css + site-chrome.css`;
- `home.css = design-system.css + styles.css + site-chrome.css + styles-v3.css`;
- `internal.css = design-system.css + styles.css + site-chrome.css + internal-pages.css`.

HTML подключает только публичные бандлы. Порядок и состав проверяет `tools/check-design-system.js`.

## Токены и компоненты

Новый код использует semantic-токены `--text-*`, `--surface-*`, `--action-*`, `--border-*`, `--shadow-*`, `--control-*`, `--layout-*`, `--radius-*`. Глобальные значения не дублируются в композиционных слоях.

Общие компоненты не должны зависеть от конкретной страницы. Утверждённая шапка главной вынесена в `src/partials/v3-header.html`, а её геометрия, состояния и адаптив вместе с футером принадлежат только `site-chrome.css`. Страничным слоям запрещено объявлять селекторы `.v3-header*`, `.v3-nav*`, `.v3-logo*` и `.v3-footer*`.

## Контракт внутренних страниц

Источник данных — manifest схемы v3 `src/data/internal-pages/index.json` и отдельные определения страниц в той же папке; шаблон — `src/templates/internal-page.html`. Manifest хранит `referenceByFamily`: эталон определяет точный визуальный контракт и critical CSS, Lighthouse проверяет все опубликованные маршруты. `PageDefinition` содержит:

- `path`, `family`, обязательный `entityRef`, `metadata.serviceType`, `breadcrumbs`;
- `hero` с изображениями, H1, lead, facts и CTA;
- `sections` с модульной композицией и настраиваемыми CTA/контактом FAQ;
- `closingCta` для заключительного контактного пролога.

Поддерживаемые семейства: `hub`, `service`, `brand`. Поддерживаемые секции: `introProof`, `serviceGrid`, `popularWorks`, `vehicleTypes`, `brandShowcase`, `editorialContent`, `symptoms`, `workStages`, `priceExamples`, `relatedIndex`, `faq`. Заменённый `brandStrip` удалён.

Без `template` порядок задаёт страница. Авторский `template: "repair-v1"` фиксирует порядок 11 типов из `page-templates.json`; resolver подставляет общие данные перед существующей валидацией и удаляет поле `template` из полного PageDefinition. Неизвестный шаблон и попытка переопределить общие данные вызывают ошибку. Validator и renderer типа находятся рядом в реестре `tools/lib/internal-pages.js`. Новый тип секции добавляется только для новой повторяемой контентной задачи и получает CSS и тест. Эталонный hub проходит полный контракт, пять новых страниц ремонта — общие проверки и адаптив на 11 ширинах, скриншоты и интерактивные сценарии на 1440/390 px.

Эталонный `hub` усиливает существующие типы без добавления нового типа секции:

- `serviceGrid` образует одну строку из шести вертикальных карточек на `>1120 px`, три колонки на `1021–1120 px`, две на `521–1020 px` и горизонтальные одноколоночные карточки без фиксированной высоты на `≤520 px`; `vehicleTypes` сохраняет сетку `3 × 2` на `>1020 px` с переходами `2 / 1`;
- `popularWorks` рендерит шестнадцать статических плиток в сетке `4 / 2 / 1`; поле `href` превращает отдельную плитку в ссылку только после появления опубликованного маршрута;
- `brandShowcase` переиспользует композицию главной: три официальные карточки и двадцать марок в матрице `5 / 4 / 2`, которая сворачивается на `≤720 px`;
- `editorialContent` рендерит лид и структурированные подразделы; три блока и объём `1 000–1 500` знаков проверяются только у эталона. На новых страницах сохраняются дополнительные пояснения Word, без обрезки под этот лимит;
- все `.container` сайта, включая hero, CTA и футер, используют общую desktop-направляющую `1312 px` с полями `36 px`; на `≤720 px` сохраняется направляющая до `520 px` с полями `14 px`;
- `symptoms` рендерит `.internal-symptoms-layout` с сеткой признаков и `.internal-inline-cta--symptoms`;
- `priceExamples` рендерит `.internal-price-content` с `.internal-price-main` и `.internal-inline-cta--prices`;
- `relatedIndex` принимает структурированные элементы `title`, `text`, `icon` и необязательный `href`; до публикации маршрута карточка остаётся статической, на desktop используется сетка `4 × 2`;
- `faq` использует split-композицию с вводной колонкой слева и единым столбцом нативных `details/summary` справа; на `≤1020 px` колонки складываются в линейный поток;
- на `>1020 px` обе CTA-панели находятся справа, на `≤1020 px` — под основным содержимым;
- этапы используют пять колонок на `≥1280 px` и вертикальный маршрут без разрыва слов на `≤1279 px`;
- крупные главы используют `--section-space-default`, компактная связка блоков — `--section-space-compact`, а на `≤720 px` все внутренние секции используют компактный ритм.

## Интерактивность

- Реальный `href` получает только опубликованный маршрут.
- Будущая услуга или марка выводится статическим элементом без hover, focus и роли кнопки.
- Телефонный CTA использует `tel:+79224488822`.
- В `main` каждой страницы `repair-v1` находятся ровно четыре `.v3-button`: hero, две inline CTA-панели и контактный пролог; в FAQ разрешена одна вторичная текстовая `tel:`-ссылка, форм нет.
- `serviceGrid` содержит ссылку на `#related-services`; `brandShowcase` выводит полную матрицу на самой внутренней странице, поэтому дополнительная ссылка на главную не нужна.
- Минимальная интерактивная цель — 44 px.
- `focus-visible`, burger, `details/summary` и mobile callbar обязательны для проверки.
- Активный раздел desktop-меню сохраняет белый текст и отмечается янтарной линией; legacy-синий активный цвет в тёмной шапке запрещён.
- Горизонтальный scroll недопустим на ширине 320–1992 px.

## Визуальный инвариант

Главная остаётся источником бренда: промышленный B2B-характер, реальные фотографии, Geologica, тёмно-синие поверхности, светлые рабочие секции и редкий жёлтый акцент. `/remont-gruzovyh-avtomobiley/` — точный эталон семейства `hub` и модульный визуальный источник других внутренних страниц, но его 11 секций не обязательны для каждого маршрута. Сохранённый референс задаёт порядок, оформление смысловых блоков и две контрастные CTA-паузы эталонного hub; его плотность, брендинг и реквизиты не входят в контракт.

## Общие данные repair-v1

`src/data/page-templates.json` хранит hero-факты, показатели `10+ / 500+ / 80% / 1–2 дня`, марки, пять этапов и контакт FAQ. Последний этап — «Выдача техники». Шапка, футер, CSS, фотографии главной и утверждённая геометрия не меняются при создании страницы. Шесть направлений, 16 работ, шесть фотокарточек, восемь признаков и десять FAQ новых страниц сохраняют читаемый кегль и высоту по содержимому.

Новые AI-изображения допустимы только как иллюстрации техники/деталей. Для них alt начинается с «Иллюстрация», а источник и prompt записаны в `docs/repair-page-image-sources.json`. Они не являются proof-фотографиями базы или ремонта.
