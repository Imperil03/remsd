# Подготовка запуска на remsd.ru

GitHub Pages остаётся noindex-превью без canonical и sitemap. Этот этап не меняет DNS, хостинг, старый сайт и индексацию. SITE_MODE управляет политикой; поля indexable удалены как неиспользуемые. 404 получает noindex в обоих режимах и не включается в sitemap.

## Проверка production-артефакта

```powershell
$env:SITE_MODE = "production"
$env:SITE_URL = "https://remsd.ru/"
npm run verify
npm run check:release
```

check:release сравнивает все canonical/og:url с маршрутом, social image и URL-поля JSON-LD — с production origin из конфигурации, sitemap — с полным набором содержательных HTML. Отсутствующие блоки, чужие/относительные URL и неправильный robots sitemap останавливают проверку. SITE_URL не может подменить ожидаемый origin проверяющей команды.

После диагностики вернуть tracked dist в preview:

```powershell
Remove-Item Env:SITE_MODE, Env:SITE_URL -ErrorAction SilentlyContinue
npm run verify
```

CI для Lighthouse строит indexable localhost-версию. Это не production-релиз, и check:release для неё намеренно не проходит.

## Карта старых адресов

Источник — sitemap старого https://remsd.ru/, прочитан 02.10.2026. Перед фактическим переносом повторно сверить sitemap и адреса из поисковых кабинетов/аналитики.

| Старый адрес | Действие при переносе |
| --- | --- |
| / | Сохранить URL, заменить сайт |
| /arenda | Постоянный серверный редирект 301 на /arenda/ |
| /contact | Постоянный серверный редирект 301 на /kontakty/ |
| /vakancii | Не переносить по текущему решению владельца; вернуть настоящий 404, не редирект на главную |

Это подготовленная карта, не действующие настройки сервера. Не заменять 301 JavaScript-переходами и не перенаправлять все отсутствующие адреса на главную. [Рекомендации Google по переносам](https://developers.google.com/search/docs/crawling-indexing/site-move-with-url-changes).

## Чеклист фактического запуска

- Сохранить старый сайт, карту адресов и сведения об аналитике; согласовать окно запуска и откат.
- На выбранном хостинге настроить HTTPS, один основной hostname, серверные редиректы, корректный HTTP 404, сжатие и кэширование. Возможности/заголовки зависят от провайдера; не менять GitHub preview ради имитации production.
- Сверить существующие ID Яндекс Метрики и иных счётчиков с владельцем. Перенести только подтверждённые счётчики и файлы/meta подтверждения Google Search Console и Яндекс Вебмастера. Проверить клики по телефону и WhatsApp; сейчас новые ID/скрипты не добавлены.
- Перед отправкой production-артефакта пройти verify и check:release; исключить localhost/GitHub URLs в SEO-разметке. GitHub preview оставить noindex.
- После переноса проверить публичные статусы, canonical/OG/JSON-LD, robots и sitemap, отсутствие случайного noindex, редиректы без цепочек и сохранённые подтверждения кабинетов.
- Отправить sitemap в поисковые кабинеты после реального запуска. Следить за 404, индексацией, кликами и реальными Core Web Vitals; лабораторный Lighthouse не заменяет полевые данные.

Запуск считается отдельной согласованной задачей; доступы и команды конкретного хостинга пока не выбраны.
