6. структурированный редакционный текст после марок;

Оформление смысловых блоков следует сохранённому референсу `docs/references/internal-hub-block-reference.png`, но его плотность, брендинг и реквизиты не копируются. Две предусмотренные inline CTA находятся в блоках признаков и цен; FAQ использует только вторичную текстовую ссылку. Форм и боковой панели нет. Все действия звонка ведут на `tel:+79224488822`.

Новые цены и оценки от 06.09.2026 отделены от них в `docs/repair-pages-wave-one.md`. Ориентиры второй волны от 07.09.2026 согласованы отдельной матрицей, см. `docs/special-equipment-pages.md`. Показатели: 10+, 500+, 80%, 1–2 дня — срок многих типовых работ.

Структурированные данные внутренней страницы: `BreadcrumbList`, `Service`, `LocalBusiness`/`AutoRepair`. Маркетинговые показатели в JSON-LD не включаются.

## Дизайн-система

- `design-system.css` — токены;
- `styles.css` — минимальный foundation;
- `site-chrome.css` — общая навигация, кнопка, callbar, шапка, футер и служебная 404;
- `styles-v3.css` — только главная;
- `internal-pages.css` — внутренние страницы.

Публичные бандлы: `base.css`, `home.css`, `internal.css`. Контракт проверяет `tools/check-design-system.js`.

`src/data/internal-pages/index.json` — manifest схемы v3 с `referenceByFamily`; каждая страница хранится отдельным JSON. `PageDefinition` включает `entityRef`, `metadata.serviceType`, настраиваемые CTA, контакт FAQ и `closingCta`. Семейства — `hub`, `service`, `brand`. Все 16 внутренних страниц используют `template: "repair-v1"` с фиксированными 11 секциями. Общие hero-факты, показатели, марки, этапы и контакт FAQ задаются только в `page-templates.json`. Страницы без шаблона сохраняют свободную композицию. Сущности и обе стороны отношений валидируются до сборки.

## Как добавлять следующую страницу

1. Определить интент и семейство страницы.
2. Подтвердить факты и текст по `.agent/SEO_STRUCTURE.md`.
3. Для аналогичной ремонтной страницы взять исходник с `template: "repair-v1"`, не копировать общие данные. Добавить отдельный `PageDefinition` в `src/data/internal-pages/` и включить его в manifest.
4. Переиспользовать существующие секции; новый тип секции вводить только для повторяемой задачи.
5. Сделать ссылку интерактивной только после появления маршрута в сборке. Количества работ и FAQ брать из утверждённого материала, не доводить искусственно до эталона. Для отдельной волны добавить приватный контентный fixture; общий PageDefinition не менять.
6. Выполнить `npm run build`, `npm run generate:critical`, `npm run verify`, `npm run test:browser`, `npm run test:lighthouse`, `git diff --check`.

Не создавать тонкие страницы формата «услуга × марка» без отдельного решения и достаточной фактуры.
