# Project Handoff

Дата: 2026-08-30

## Быстрый вход для нового агента

Читать в таком порядке:

1. `AGENTS.md` — правила работы и запреты.
2. `.agent/SEO_STRUCTURE.md` — публичный контур, семейства страниц и SEO-архитектура.
3. Этот файл — текущее состояние и ближайший рабочий контракт.
4. `docs/project-history.md` — почему проект пришёл к текущему состоянию.
5. Для дизайна: `docs/design-guideline.md` → `docs/design-system.md` → `DESIGN.md`.
6. Для реализации: `src/data/internal-pages.json`, `src/templates/internal-page.html`, `assets/css/internal-pages.css`.

## Текущий статус

Сайт приведён к чистой точке старта многостраничной разработки. Публичная сборка содержит только:

- утверждённую главную `/`;
- эталонный hub `/remont-gruzovyh-avtomobiley/`;
- `404.html`.

Прежние внутренние маршруты, их шаблоны, стили и определения удалены. В будущем страницы создаются заново, а не мигрируют автоматически.

## Эталонная внутренняя страница

Страница ремонта грузовых автомобилей использует визуальный язык главной: тёмный фото-hero, Geologica, реальные фотографии базы, сдержанный жёлтый акцент, большой межсекционный ритм и общую шапку. Композиция включает:

1. intro/proof split с фотографией и четырьмя показателями;
2. шесть равноправных карточек направлений ремонта;
3. шесть карточек типов техники с фотографией и подписью;
4. компактную строку из девяти марок;
5. шесть рамочных карточек признаков неисправности;
6. пять связанных карточек этапов с пиктограммами;
7. две таблицы с восемью примерами цен;
8. светлую сетку из восьми будущих направлений;
9. двухколоночный FAQ из 11 нативных `details/summary`;
10. контактный пролог футера.

Оформление смысловых блоков следует сохранённому референсу `docs/references/internal-hub-block-reference.png`, но его плотность, брендинг, реквизиты и CTA не копируются. Межсекционный ритм остаётся более свободным по токенам РемСД. Асимметричная фотомозаика, тёмный индекс, тёмная первая карточка этапов и split/sticky FAQ не используются. CTA есть только в hero, контактном прологе и мобильной callbar. Форм, боковой панели и промежуточных CTA нет. Все CTA звонка ведут на `tel:+79224488822`.

Иерархия визуальных источников:

1. утверждённая главная задаёт бренд, типографику, цвет, шапку, футер и общий уровень воздуха;
2. сохранённый референс задаёт порядок и оформление смысловых блоков эталонного hub;
3. живая страница `/remont-gruzovyh-avtomobiley/` является текущей принятой реализацией этого сочетания;
4. прежние варианты `/remont/` и отклонённая версия с фотомозаикой не являются источниками дизайна.

## Данные и факты

В `site-config.json` зафиксированы реквизиты РемСД, график `ежедневно с 08:00 до 22:00` и подтверждённые владельцем факты. Ориентировочные цены действуют с 29.08.2026; точная стоимость определяется после диагностики, а НДС и состав запчастей уточняются при согласовании.

Структурированные данные внутренней страницы: `BreadcrumbList`, `Service`, `LocalBusiness`/`AutoRepair`. Маркетинговые показатели в JSON-LD не включаются.

## Дизайн-система

- `design-system.css` — токены;
- `styles.css` — foundations/shared;
- `site-chrome.css` — общая шапка, футер и служебная 404;
- `styles-v3.css` — только главная;
- `internal-pages.css` — внутренние страницы.

Публичные бандлы: `base.css`, `home.css`, `internal.css`. Контракт проверяет `tools/check-design-system.js`.

`src/data/internal-pages.json` хранит `PageDefinition`: `path`, `family`, `metadata`, `breadcrumbs`, `hero`, `sections`. Семейства — `hub`, `service`, `brand`; набор секций определяется страницей.

## Как добавлять следующую страницу

1. Определить интент и семейство страницы.
2. Подтвердить факты и текст по `.agent/SEO_STRUCTURE.md`.
3. Добавить новый `PageDefinition` в `internal-pages.json`.
4. Переиспользовать существующие секции; новый тип секции вводить только для повторяемой задачи.
5. Сделать ссылку интерактивной только после появления маршрута в сборке.
6. Выполнить `npm run verify`, `npm run test:browser`, `git diff --check`.

Не создавать тонкие страницы формата «услуга × марка» без отдельного решения и достаточной фактуры.

## Репозиторий и история

`main` содержит точное опубликованное дерево GitHub Pages. Детальные рабочие коммиты текущей итерации сохранены в `codex/remsd-seo-pilots`; их краткая карта приведена в `docs/project-history.md`. При продолжении разработки ориентироваться на файлы из `main`, а историю использовать для понимания причин решений, а не для восстановления удалённых шаблонов.
