# Страницы марок грузовиков

23 страницы семейства `brand` используют шаблон `brand-v1`. Их маршруты — `/remont/{марка}/`, исходники — `src/data/internal-pages/brand-{марка}.json`. Эталон брендовой страницы — КАМАЗ. Страницы входят в общий manifest и собираются тем же процессом, что и остальные внутренние страницы.

## Источники и редактура

- Техническая основа — предоставленный владельцем документ `Бренды.docx`. Названия моделей, агрегатов, работы и оговорки о комплектации сохраняются; карту переноса содержит `docs/brand-source-map.json`.
- Документы сервиса, согласование сметы и дополнительных работ, акт и гарантийные документы подтверждены правилами проекта. Контакты и график берутся из `site-config.json`.
- Официальный статус относится только к КАМАЗ, МАЗ и УРАЛ. Упоминание трёх официальных марок в общем каталоге не распространяет статус на текущую марку.
- У УРАЛ сохранены семь направлений. У SANY разделены грузовая и специальная техника. Для SANY и Sitrak используются подтверждённые типы техники без выдуманного перечня моделей.
- Word — источник редакционной работы, а не зависимость сборки. Для сборки нужны только версионируемые JSON и ресурсы проекта.

## Композиция

После фирменного первого экрана идут 11 секций в фиксированном порядке:

| Тип секции | Назначение |
|---|---|
| `introProof` | Вступление, реальное фото базы и подтверждённые условия работы |
| `serviceGrid` | 5–7 направлений ремонта с конкретными операциями |
| `popularWorks` | Компактный перечень работ из документа |
| `modelRange` | Модели, серии или типы техники |
| `brandShowcase` | Общий каталог 23 марок с отметкой текущей страницы |
| `editorialContent` | Три подраздела о технических особенностях |
| `symptoms` | Признаки неисправности и звонок мастеру |
| `workStages` | Пять общих этапов ремонта |
| `costEstimate` | Порядок расчёта стоимости и звонок мастеру |
| `relatedIndex` | Связанные опубликованные направления |
| `faq` | 3–4 вопроса перед обращением в сервис |

Страницу завершает контактный блок. Основные телефонные кнопки находятся в первом экране, симптомах, стоимости и заключении. FAQ содержит вторичную текстовую ссылку. Общая мобильная панель дополняет эти действия.

Для длинных технических описаний используются списки, короткие абзацы и подзаголовки. Содержательные карточки направлений имеют три колонки на широком экране. Новые секции используют существующие шрифты, цвета, направляющие и адаптивные правила. Фото базы не подписываются как ремонт определённой марки без подтверждения.

## Данные и расширение

Общие этапы, каталог марок и контакт FAQ разрешаются через `page-templates.json`; их не следует копировать в файлы отдельных страниц. У брендового шаблона собственные текстовые факты и условия работы: договор, смета, согласование и документы. Новые поля:

- `serviceGrid.items[].details` — необязательный непустой массив строк с операциями.
- `modelRange.items[]` — `title`, `text`, необязательный непустой массив `models`; у секции допускается `note`.
- `costEstimate.items[]` — `title`, `text`, `icon`; секция также содержит обязательные `note` и `cta` с полями `title`, `text`, `buttonLabel`.

В блок стоимости не добавляются числовые цены: документ их не содержит. Здесь объясняются диагностика, объём работ, детали и согласование. Добавлять будущие ссылки можно только после включения соответствующего маршрута в сборку. Страницы «услуга × марка» не создаются.

В каталоге текущая марка — статический элемент с `aria-current="page"`; остальные марки ведут на опубликованные страницы. Главная, меню и внутренние каталоги используют те же маршруты. Canonical, sitemap, preview `noindex` и JSON-LD сохраняют общие правила сборки; `Offer`, `FAQPage`, рейтинги и отзывы не добавляются.

## Проверки

`npm run verify`, `npm run test:browser` и `git diff --check` — обязательные проверки. `tools/lib/check-brand-pages.js` подключается к общей проверке сайта и контролирует 23 маршрута, порядок секций, четыре основные кнопки, ограничения официального статуса, вывод моделей и операций, FAQ, активацию ссылок и ошибочные новые структуры данных. Карта переноса задаёт точные количества направлений, работ, технических подразделов и моделей каждой марки; Word для проверки сборки не нужен.

Визуально проверяются широкая и мобильная версии, отдельно — семь направлений УРАЛ, смешанная техника SANY, типы техники Sitrak и длинные названия марок. Важны отсутствие горизонтальной прокрутки и перекрытий мобильной панелью, читаемость списков и работа аккордеонов.
