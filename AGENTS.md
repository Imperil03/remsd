# AGENTS.md

## Проект

РемСД — статический сайт сервисного центра по ремонту грузовых автомобилей и спецтехники в Сургуте.

Рабочий продакшен-превью:
- GitHub Pages: https://imperil03.github.io/remsd/

Внешний домен компании:
- https://remsd.ru/

## Главный SEO-фокус

1. Главная страница: ремонт грузовых автомобилей в Сургуте.
2. Главная страница: ремонт спецтехники в Сургуте.
3. Официальный сервис и ремонт КАМАЗ, МАЗ, УРАЛ в Сургуте — отдельный брендовый коммерческий слой и proof-сигнал на главной.
4. Ремонт агрегатов грузовых автомобилей и спецтехники: двигатель, ГБЦ, КПП, ходовая, тормоза, гидравлика, электрика, топливная система, охлаждение, SCR/AdBlue, ТО.
5. Аренда спецтехники — отдельное направление, не смешивать с ремонтом.

## Где лежит контекст

- `.agent/SEO_STRUCTURE.md` — актуальная SEO-архитектура и запрет на тонкие страницы "услуга × марка".
- `docs/project-handoff.md` — состояние проекта, что уже сделано и как продолжать.
- `docs/design-guideline.md` — визуальные правила.
- `src/data/site-config.json`, `entities.json`, `relations.json`, `internal-pages.json` — типизированная модель сайта и внутренних страниц.
- `.agent/agents/` — роли текстового автора и ревьюера.
- Подтвержденные публичные факты сейчас берутся из существующего контента сайта, сертификатов/документов в проекте, `.agent/SEO_STRUCTURE.md` и явно указанных пользователем источников. Не восстанавливать удаленные `.agent/CONTENT_GUIDE.md` и `.agent/CLAIMS_LEDGER.md` без отдельного запроса.
- Владелец разрешил прямо публиковать документы и реальные обязательства сервиса: работу по договору, заказ-наряд, согласование сметы, срока и дополнительных работ, акт выполненных работ и гарантийные документы. Это не относится к выдуманным ценам, числовым срокам или расширению области гарантии без отдельного решения владельца.

## Как работать

- Сначала читать `.agent/SEO_STRUCTURE.md` и `docs/project-handoff.md`.
- Не добавлять отдельные страницы вида `/remont-gbc-kamaz/`, `/remont-kpp-maz/`, `/remont-elektriki-ural/` без отдельного решения.
- Новые страницы сначала отнести к семейству `hub`, `service` или `brand`, затем добавить подтверждённые сущности, отношения и `PageDefinition` в `internal-pages.json`.
- После изменений проверять:

```bash
npm run verify
npm run test:browser
git diff --check
```

## Деплой

`dist/` отслеживается в git и используется GitHub Pages workflow. После сборки нужно коммитить и исходники, и обновленный `dist/`.

## Project Skills

- Vendored skills больше не хранятся в `.agent/skills/`. Не восстанавливать их без отдельного запроса.
- Перед работой с дизайном или текстами читать `docs/skills.md`, `.agent/SEO_STRUCTURE.md` и `docs/design-guideline.md`.
- Для публичного русского текста использовать цепочку: `SEO_STRUCTURE` -> существующий контент и явно указанные источники фактов -> спокойная B2B-редактура -> reviewer для SEO/коммерческих текстов.
- Внешние skills текущей Codex-сессии носят рекомендательный характер. Они не должны перебивать B2B-стиль РемСД, SEO-структуру, фактический тон и запрет на фейковые цены, сроки, гарантии, рейтинги, отзывы и манипулятивную срочность.
